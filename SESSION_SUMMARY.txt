OVERVIEW
--------
A system that monitors access to sensitive credential/config artifacts (.aws,
.ssh, .azure, .kube, .steampipe) on Linux servers, establishes a baseline of
normal behavior, and flags deviations with explainable risk scores — both in
batch mode and in real time as events are collected.

ANOMALY DETECTION MODEL
-----------------------
Discrete Bayesian Network (pgmpy) with 8 nodes, 8 edges:

    artifact ──┬── process ──┬── time_delta ── session_size
               ├── user ── hour_bucket ── day_bucket
               └── access_type

Nodes:
  artifact     : azure, aws, ssh, kube, steampipe (dynamic from data)
  process      : bash, cat, head, tail, nano, python3, curl, wget, ssh,
                 grep, less, other
  user         : root, debian, other
  access_type  : read, write, create, delete, moved
  hour_bucket  : night, early, morning, midday, afternoon, evening
  day_bucket   : weekday, weekend
  time_delta   : instant (<0.1s), rapid (0.1-1s), normal (1-60s),
                 slow (1-10min), idle (>10min)
  session_size : single (1), small (2-5), medium (6-20), large (21-50),
                 burst (51+)

- Trained ONLY on normal events (session_id NOT LIKE 'attack_%') —
  attack data is held out for evaluation, never trained on.
- Laplace smoothing (alpha=1.0) for unseen combinations.
- Timing features (time_delta, session_size) get 2x weight in scoring —
  burst attacks are the highest-signal pattern.
- Model persisted to ml/anomaly_model.json; collector auto-loads at startup.

RISK THRESHOLDS (calibrated on labeled data, 2026-09-16)
--------------------------------------------------------
Measured distributions (seed-42 dataset — generator is now seeded,
default seed 42, so these numbers reproduce exactly):
  NORMAL events: risk <= 20.6
  ATTACK events: risk 26.5 – 29.4

Classification (ml/anomaly_detector.py):
  risk >= 45  -> ANOMALY    (magenta)
  risk >= 27  -> SUSPICIOUS (red)     <-- attacks land here
  risk >= 23  -> UNUSUAL    (yellow)
  else        -> NORMAL     (green)

The 22.3/27.9 gap gives clean separation; thresholds sit in the gap
(23 / 27 / 45). Attacks escalate to SUSPICIOUS in both batch and
real-time output.

REAL-TIME SCORING (NEW)
-----------------------
collector.py loads ml/anomaly_model.json at startup and scores every event
immediately after insertion:
  NORMAL     -> INFO   "risk: NORMAL (score=...)"
  non-normal -> WARNING "RISK ALERT: SUSPICIOUS (risk=30.7/100) — P(...)=..."
Scoring failures never crash the collector (caught + logged at debug).
If no trained model exists, collector runs fine with scoring disabled and
prints a warning pointing to `python ml/anomaly_detector.py train`.

Live smoke test (2026-09-16): touch+rm inside ~/.azure produced 8 events,
auditd resolved pid/comm/user (rm), rapid-delta events triggered inline
RISK ALERT: SUSPICIOUS — verified end-to-end.

HOW TO RUN
----------
# 0. Activate environment
source venv/bin/activate

# 1. Health check
python -c "import yaml, watchdog, pgmpy; print('deps OK')"
python db.py

# 2. (Optional) regenerate demo data from scratch
python -c "from db import get_conn; c=get_conn(); c.execute('DELETE FROM events'); c.execute('DELETE FROM baseline'); c.commit(); c.close()"
python ml/generate_test_events.py     # 400 normal + 180 attack events

# 3. Baseline
python baseline.py --reset            # compute + display
python baseline.py --show             # view anytime

# 4. Anomaly detection
python ml/anomaly_detector.py train         # train on normal sessions only
python ml/anomaly_detector.py score-all     # batch score + flagged events
python ml/anomaly_detector.py score-all --report   # + write alerts.json
python ml/anomaly_detector.py evaluate      # precision/recall/F1/confusion matrix
python ml/anomaly_detector.py explain <id>  # per-event probability breakdown
python ml/anomaly_detector.py status        # model info

# 5. Live demo (2 terminals)
python collector.py                  # terminal 1: watch + real-time score
echo test >> ~/.azure/config         # terminal 2: trigger an event
# terminal 1 shows Event #N + risk: NORMAL / RISK ALERT lines; Ctrl+C stops
# (audit rules are removed automatically on shutdown)

KNOWN LIMITATIONS:
  ⚠️ Evaluation uses synthetic attacks — real-world FP rate unverified
     (synthetic normal data is cleaner than production noise).
  ⚠️ No sequence analysis — individual events are scored, not attack chains
     (e.g. cat id_rsa → append authorized_keys).
  ⚠️ No alerting destinations beyond stdout/alerts.json (no syslog/email/webhook).
  ⚠️ Risk scores cluster narrowly (27.9–30.9 for attacks) — ANOMALY level is
     rarely reached; threshold 45 is a placeholder pending more diverse data.
  ⚠️ detector trained model must be regenerated after major feature changes
     (model and scoring features must stay in sync).

DESIGN PRINCIPLES
-----------------
1. Context over content — accessing .azure/config isn't inherently malicious;
   who, when, and in what sequence determines risk.
2. Explainability — every flag carries per-factor probabilities.
3. Low false-positive rate — train on normal only; evaluate against labeled data.
4. Sequence-awareness (partial) — burst timing is modeled; full attack chains
   are future work.
